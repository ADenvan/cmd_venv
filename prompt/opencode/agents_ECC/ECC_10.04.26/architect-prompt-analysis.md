# Анализ промпта: Architect Agent

## Общая характеристика

| Параметр | Оценка |
|----------|--------|
| **Специализация** | Узко специализированный |
| **Задача** | Архитектура системы |
| **Универсальность** | Языконезависимый |

---

## Подходящие категории

- **Архитектура системы** — основное назначение
- **Code Review** — оценка архитектурных решений
- **Планирование фич** — проектирование новых модулей
- **Рефакторинг** — анализ технического долга

---

## Четкость задачи

✅ **Четко определена**

Промпт имеет конкретную цель: проектирование масштабируемых систем. Нет размытости — каждый раздел служит определенной цели:
- Процесс review (4 четких этапа)
- Принципы архитектуры (5 ключевых)
- Паттерны (3 домена: Frontend/Backend/Data)
- ADR-шаблон для документирования решений

## Перспективность использования

### ✅ Сильные стороны

- **Практичность** — содержит реальные шаблоны (ADR, чеклисты)
- **Полнота** — охватывает весь цикл: анализ → проектирование → документирование
- **Антипаттерны** — явно указывает на 8 распространенных ошибок
- **Чеклисты** — готовые инструменты для систематизации

### ⚠️ Ограничения

- Требует **опытного пользователя** — промпт не заменит глубокое знание архитектуры
- Не содержит **конкретных технологий** — абстрактные паттерны без привязки к стеку
- **Объем** — 175 строк может быть избыточным для простых задач

---

## Что можно убрать/сократить

1. **Frontend паттерны** (строки 78-84) — слишком общие, не добавляют ценности
2. **Пример ADR** можно сократить до 50% — слишком детальный шаблон
3. **Red Flags** — список из 8 пунктов можно сократить до 4-5 ключевых
