Ты мыслишь в правильном направлении, но текущая структура может привести к «размытому» пониманию контекста у AI. Проблема в том, что «анализ» и «отчет» часто пересекаются по смыслу, а границы между этапами нечеткие.

Вот исправленная **многоуровневая система блоков**, где каждый уровень имеет четкий «контракт» для AI:

---

### 🎯 Уровень 0: МЕТА-КОНТЕКСТ (обязателен всегда)
```
[TASK_TYPE]: Отчетно-аналитическая задача
[DOMAIN]: Финансы/HR/Логистика/IT (конкретика)
[COMPLEXITY]: Синтез → Требуется объединение данных из разных источников
[OUTPUT_FORMAT]: Таблица + выводы + график
```

### 📥 Уровень 1: ИСТОЧНИК (Source)
```
[DATA_TYPE]: CSV/PDF/Текст/База данных
[DATA_STATE]: Сырой/Частично обработанный/Структурированный
[EXTRACTION_RULES]:
  - Поля для извлечения: [список]
  - Фильтры: [условия отбора]
  - Игнорировать: [что исключить]
```

### 🔍 Уровень 2: ОБРАБОТКА (Processing) — разделен на подэтапы
```
[PARSING]: Преобразование сырого формата в структуру
[CLEANING]: Удаление дубликатов, исправление типов данных
[ANALYSIS_TYPE]:
  - Дескриптивный (что произошло)
  - Диагностический (почему произошло)
  - Предиктивный (что будет)
[CONSTRAINTS]: Не использовать внешние данные / Только внутренняя аналитика
```

### 🧠 Уровень 3: СИНТЕЗ (Synthesis) — твоя схема «проблема-решение»
```
[PROBLEM_STATEMENT]: Сформулировать проблему одним предложением
[ROOT_CAUSE_CHAIN]:
  1. Первопричина → 2. Промежуточная причина → 3. Следствие
[SOLUTIONS]:
  - Быстрое (временное)
  - Стратегическое (долгосрочное)
[IMPACT_ASSESSMENT]:
  - Риски внедрения
  - Ожидаемый ROI/эффект
```

### 📊 Уровень 4: ПРЕДСТАВЛЕНИЕ (Output)
```
[VISUALIZATION]: Таблица/График/Дашборд/Текст
[STRUCTURE]:
  - Сводка (3 bullet points)
  - Детализация (таблица)
  - Рекомендации (приоритезированный список)
[ACTION_ITEMS]: Кто/что/когда
```

---

### ✅ Пример запроса к AI с такой структурой:

```
[METА]
TASK_TYPE: Анализ оттока клиентов
OUTPUT_FORMAT: Таблица + приоритезация

[SOURCE]
DATA_TYPE: CSV (clients_q3.csv)
EXTRACTION_RULES: колонки [id, last_purchase, complaints, segment]

[PROCESSING]
ANALYSIS_TYPE: Диагностический (корреляция жалоб и оттока)

[SYNTHESIS]
PROBLEM: Отток вырос на 15% в Q3
ROOT_CAUSE: Длительное время ответа на жалобы → снижение лояльности

[OUTPUT]
VISUALIZATION: Таблица с сегментами + график тренда
ACTION_ITEMS: Для каждого сегмента конкретные шаги
```

### ⚠️ Твои ошибки (исправлено):

1. **«Отчет → Анализ → Результат»** — это линейно, но AI путает «отчет» (input) и «результат» (output). Лучше использовать **Input → Processing → Output**.

2. **Отсутствие типа анализа** — без указания `[ANALYSIS_TYPE]` AI может сделать описательный анализ вместо диагностического, когда тебе нужно найти причины.

3. **Неявные границы** — блок `[SOURCE]` отделяет «что есть» от «что делаем», предотвращая ситуацию, когда AI начинает анализировать до прочтения файла.

### 🛠️ Как использовать:

**Если задача простая** (пересчитать таблицу):
- Используй только `[SOURCE]` + `[OUTPUT]`

**Если задача сложная** (анализ + рекомендации):
- Все 5 уровней, но `[SYNTHESIS]` можно сократить до `[PROBLEM]` + `[SOLUTIONS]`

**Если нужна итеративная работа**:
Добавь `[FEEDBACK_LOOP]` — блок для уточнения промежуточных результатов перед финальным выводом.

Такая структура работает как «типизация» для AI — он понимает, в каком режиме работать, и не смешивает этапы сбора данных с этапом вывода гипотез.
