# Точка входа в Python-пакете

## Основной паттерн: `main.py` внутри пакета
Структура пакета:

```
my_package/
├── __init__.py
├── main.py          # ← точка входа
├── module1.py
└── module2.py
```

## Пример реализации
**`my_package/main.py`:**

```python
def main():
    print("Приложение запущено!")
    # Основная логика здесь
if __name__ == "__main__":
    main()
```

## Настройка entry point в `pyproject.toml`
```toml
[project.scripts]
myapp = "my_package.main:main"
```
После установки пакета команда `myapp` будет доступна в терминале.

## Альтернатива: `__main__.py`
Для запуска через `python -m my_package` создайте:
**`my_package/__main__.py`:**

```python
from my_package.main import main
if __name__ == "__main__":
    main()
```

## Ключевые моменты
| Подход | Команда запуска | Назначение |
|--------|-----------------|------------|
| `main.py` + `pyproject.toml` | `myapp` | Установленная CLI-команда |
| `__main__.py` | `python -m my_package` | Модульный запуск |

**Рекомендация:** Используйте `main.py` внутри пакета как основную точку входа — это стандартный и предсказуемый паттерн.

Отличный вопрос! Объясню просто:
## Зачем нужен `pyproject.toml`
Это **файл настроек** вашего Python-пакета. В нём pip узнаёт:
- как установить ваш пакет
- какие зависимости нужны
- **какие команды создать в терминале**

Без этого файла pip не поймёт, что у вас вообще пакет, а не просто набор файлов.
---

## Что значит эта запись
```toml
[project.scripts]
myapp = "my_package.main:main"
```

Разберём по частям:

| Часть | Значение |
|-------|----------|
| `myapp` | Имя команды в терминале (вы будете писать `myapp` и жать Enter) |
| `my_package` | Имя вашей папки с пакетом |
| `main` (до двоеточия) | Имя файла `main.py` |
| `main` (после двоеточия) | Имя функции внутри файла |

**По-русски:** "Когда пользователь напишет `myapp` в терминале — запусти функцию `main()` из файла `my_package/main.py`"

---

## Пример
После установки пакета:
```bash
pip install .

# Теперь работает:
myapp          # → запускает вашу функцию main()
```

Без `pyproject.toml` пришлось бы писать длинную команду:
```bash
python -c "from my_package.main import main; main()"
```
А с ним — просто `myapp`.

## `pip install -e .` — установка в "редактируемом" режиме

### Что делает
| Команда | Результат |
|---------|-----------|
| `pip install .` | Копирует пакет в систему, изменения в коде **не видны** |
| `pip install -e .` | **Создаёт ссылку** на вашу папку, изменения **сразу работают** |
---

### Зачем нужен флаг `-e` (editable)
**Без `-e`:**
```bash
pip install .
# Пакет скопирован в /usr/lib/python3.x/site-packages/

# Вы меняете код → запускаете → видите СТАРУЮ версию
# Нужно переустанавливать каждый раз!
```

**С `-e`:**
```bash
pip install -e .
# Создана символическая ссылка на вашу папку

# Вы меняете код → запускаете → видите НОВУЮ версию
# Переустанавливать не нужно!
```
---

### Когда использовать
```
Разработка пакета  →  pip install -e .
Продакшен/релиз    →  pip install .
```
---
### Пример workflow
```bash
# 1. Перейти в папку проекта
cd my_project

# 2. Установить в редактируемом режиме
pip install -e .

# 3. Теперь команда myapp работает и видит все изменения
myapp
```

**Коротко:** `-e` = **development mode**. Код работает "напрямую" из вашей папки, без копирования.
