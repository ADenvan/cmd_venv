В VS Code есть **встроенный и более стабильный способ** создания виртуальных окружений, который обходит большинство проблем терминала (зависания `ensurepip`, права доступа, блокировки антивируса).

Следуйте этой инструкции по шагам:

---

### ✅ Способ 1: Через интерфейс VS Code (Рекомендуется)
1. Убедитесь, что установлены официальные расширения:
   - `Python` (от Microsoft)
   - `Python Debugger`
2. Откройте палитру команд: `Ctrl + Shift + P`
3. Введите и выберите: **`Python: Create Environment`**
4. Выберите тип: **`Venv`**
5. Выберите интерпретатор: **`Python 3.13`** (должен появиться в списке)
6. VS Code создаст папку `.venv`, установит `pip` и предложит **перезагрузить окно**. Нажмите `Reload`.
7. Откройте новый терминал (`Ctrl + `` `). В начале строки должно появиться `(.venv)`.

> 💡 *Почему это лучше:* VS Code сам настраивает пути, обходит блокировки терминала и корректно регистрирует окружение в системе.

---

### 🔧 Способ 2: Через терминал (если UI зависает или выдаёт ошибку)
Если первый способ не сработал, создайте окружение вручную, но **без этапа установки pip** (это обходит `KeyboardInterrupt`/зависание):

```powershell
# 1. Удалите сломанную папку (если осталась)
Remove-Item -Recurse -Force .venv

# 2. Создайте venv без pip
python -m venv .venv --without-pip

# 3. Активируйте
.\.venv\Scripts\activate

# 4. Установите pip вручную (быстро и без зависаний)
python -m ensurepip --upgrade

# 5. Обновите pip и установите зависимости
python -m pip install --upgrade pip
pip install django  # или ваш requirements.txt
```

---

### ⚙️ Настройка VS Code для работы с `.venv`
После создания окружения выполните эти действия, чтобы VS Code всегда использовал его:

1. `Ctrl + Shift + P` → **`Python: Select Interpreter`**
2. Выберите путь: `./.venv/Scripts/python.exe` (или `.venv\Scripts\python.exe`)
3. Откройте настройки: `Ctrl + ,` → в поиске введите `Activate Env`
4. Убедитесь, что **`Python > Terminal: Activate Environment`** включено ✅
5. Перезапустите терминал (`Ctrl + Shift + P` → `Terminal: Create New Terminal`)

Теперь при каждом открытии терминала в этом проекте VS Code будет автоматически активировать `(.venv)`.

---

### 🛡️ Если окружение всё равно не создаётся или зависает
| Причина | Решение |
|--------|---------|
| **Антивирус блокирует `ensurepip`** | Временно отключите защиту (Kaspersky/Defender) на 2 минуты при создании `.venv` |
| **Нет прав на запись в `C:\Python313\`** | Запустите VS Code **от имени администратора** только на время создания venv |
| **`python` указывает не на 3.13** | Проверьте: `python -c "import sys; print(sys.executable)"`. Если путь неверный, используйте `py -3.13 -m venv .venv` |
| **Прокси/корпоративная сеть** | Добавьте в переменные окружения: `SET PIP_TRUSTED_HOST=pypi.org` перед установкой пакетов |

---

### ✅ Финальная проверка
В терминале VS Code должно выглядеть так:
```powershell
(.venv) PS D:\Python-Project\Django\pay_brother_v3> python -V
Python 3.13.x
(.venv) PS D:\...\pay_brother_v3> pip -V
pip 24.x.x from D:\...\pay_brother_v3\.venv\Lib\site-packages\pip (python 3.13)
```

Если всё прошло успешно, вы можете запускать Django так:
```powershell
python manage.py runserver
```

Напишите, на каком шаге возникла проблема (если осталась), или пришлите вывод `python -c "import sys; print(sys.prefix)"` после активации `.venv`. Помогу довести до рабочего состояния.
