1. Описание проекта
Веб-приложение для автоматизированного расчёта заработной платы сотрудников. Система обеспечивает ведение справочников персонала, управление трудовыми договорами, гибкий расчёт начислений и удержаний с учётом актуального законодательства, формирование расчётных листков и аналитической отчётности. Предназначено для бухгалтеров, HR-специалистов и руководителей, с строгим разграничением прав доступа до уровня отдельных сотрудников. Ключевая ценность: прозрачность расчётов, минимизация ручных операций, соответствие требованиям налогового и трудового учёта.

2. Функциональные требования
Управление доступом и ролями (RBAC):
Роли: admin, accountant (расчёты/справочники), manager (просмотр своего отдела), employee (только свой расчётный листок).
Аутентификация, сессии, восстановление паролей, двухфакторная опциональная защита.
Справочники и сотрудники:
Карточки сотрудников, история трудоустройства, должности, отделы, графики работы.
Контракты с типом оплаты (оклад/почасовая/сдельная), базовой ставкой, валютой, датами действия.
Расчётный движок:
Виды выплат: оклад, премии, надбавки (за выслугу, вредность, ночные), отпускные, больничные, командировочные, материальная помощь.
Удержания: НДФЛ, страховые взносы, алименты, профсоюзные, исполнительные листы.
Динамическое применение ставок/коэффициентов с привязкой к датам и регионам.
Учёт отработанных дней/часов, сверхурочных, простоев, неполного месяца.
Пошаговый статусный процесс периода: черновик → рассчитан → проверен → утверждён → выплачен.
Отчётность и экспорт:
Формирование индивидуальных расчётных листков и сводных ведомостей.
Экспорт в Excel и PDF, визуализация аналитики (графики по отделам/периодам/статьям расходов).
Аудит и логирование: Фиксация всех изменений ставок, окладов, ручных корректировок и смены статусов (пользователь, дата, старое/новое значение).
Интеграции (опционально): Массовый импорт/экспорт из Excel, подготовка REST API для 1С/банк-клиента, email/Telegram-уведомления о готовности расчётки.

3. Технологический стек
Backend: Python 3.10+, Django 4.2+/5.x. Модульная структура: users, employees, payroll, settings, reports.
Дополнительно: Celery + Redis (фоновые расчёты, рассылки), django-auditlog (аудит изменений), django-import-export (загрузка справочников), django-filter + HTMX (динамические интерфейсы без тяжёлого JS).
Frontend: HTML5, CSS3 (Flexbox/Grid, адаптивная вёрстка), JavaScript (vanilla + лёгкие фреймворки: Alpine.js/HTMX для интерактивности).
Библиотеки: DataTables.js/AG Grid (таблицы с сортировкой/фильтрацией), Chart.js/ApexCharts (аналитика), WeasyPrint/OpenPyXL (генерация PDF/Excel на сервере). Клиентская валидация дублируется строгой серверной.
База данных: PostgreSQL 14+.
Типы: NUMERIC(12,2) для денежных значений, DATE/TIMESTAMPTZ для периодов, ENUM для статусов, JSONB для гибких метаданных.
Механизмы: транзакции (atomic()), индексы по employee_id, period_id, valid_from, CHECK-констрейнты (amount >= 0), партиционирование таблиц расчётов по периодам при росте >500к записей.
Инфраструктура: Docker + docker-compose, Nginx (reverse proxy, TLS/HTTPS), Gunicorn/Uvicorn, Sentry (мониторинг ошибок), GitHub Actions/GitLab CI (линтеры, тесты, деплой).

4. Ограничения и требования
Финансовая точность: Запрещено использовать float или double. Все расчёты строго через Decimal/NUMERIC. Округление до 2 знаков по бухгалтерскому стандарту (согласовано с ТЗ). Расхождения в копейках недопустимы.
Юридическая гибкость: Налоговые ставки, МРОТ, региональные коэффициенты, лимиты взносов не хардкодятся. Хранятся в БД с полями valid_from/valid_to. Обновление происходит без перезапуска приложения и через интерфейс администратора.
Безопасность и конфиденциальность: Соответствие 152-ФЗ/GDPR. Данные передаются только по HTTPS. Строгий RBAC на уровне ORM (filter(owner=request.user)), защита от CSRF/XSS/SQLi средствами Django. Чувствительные поля при необходимости шифруются на уровне приложения или БД.
Надёжность и отказоустойчивость: Атомарность расчёта периода, блокировка периода на время вычислений (status = 'calculating'), ежедневные бэкапы БД с регулярным тестированием восстановления. Логирование всех финансовых операций хранится не менее 3 лет.
Производительность: Массовые расчёты (500+ сотрудников) выносятся в асинхронные задачи (Celery). Используется select_related/prefetch_related, кэширование справочников ставок, оптимизация PostgreSQL (shared_buffers, work_mem, autovacuum).
Тестирование и поддержка: 100% покрытие юнит-тестами ядра расчёта (граничные случаи: отпуск в середине месяца, больничный, увольнение, переход года, нулевые выплаты). Интеграционные тесты полного цикла: расчёт → проводка → отчёт. Обязательная документация формул, карта прав доступа, регламент обновления ставок/законов.
