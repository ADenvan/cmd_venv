## Как это работает в вашем CLI

```bash
# 1. Пользователь копирует файлы проекта (или делает tree + cat ключевых файлов)
# 2. Вызывает Scanner с этим промптом как System Prompt
agent scanner --input ./myproject_files.txt --output as_is_v1.2.md

# 3. Scanner выдает отчет
# 4. Пользователь сохраняет файл
# 5. Передает Архитектору
agent architect --context as_is_v1.2.md --task "Добавить систему подписок"
```

Независим от стадии?
  - Да. Определяет стадию автоматически и адаптирует глубину анализа.
Версионируется?
  - Да. Синхронно с Архитектором. as_is_v1.0.md → архитектура v1.0 → as_is_v1.1.md → архитектура v1.1.
Что если проект пустой?
  - Честно пишет AS-IS: Empty project. — Архитектор строит с нуля.
Может ли он видеть N+1 и циклические импорты?
  - Да, но только фиксирует факт. Лечение — задача Архитектора.
Нужно ли ему знать предыдущую архитектуру?
  - Нет обязательно, но если пользователь предоставит — сравнит в разделе Drift.

as_is_v1.0.md      →  Architect designs v1.0  →  implementation
       ↓                    ↓
as_is_v1.1.md      →  Architect designs v1.1  →  new feature
       ↓                    ↓
as_is_v2.0.md      →  Architect designs v2.0  →  refactoring

Правило: Версия AS-IS отчета = версия архитектуры, которую он отражает. Когда вы делаете рефакторинг по архитектуре v2.0, следующий скан становится as_is_v2.0.md (или v2.1 если добавили фичу без рефакторинга).



Глубоко, но структурированно. Scanner анализирует:

| Уровень         | Что видит Scanner                         | Пример                                    |
| --------------- | ----------------------------------------- | ----------------------------------------- |
| **Файлы/папки** | Структура, имена, расположение            | `apps/blog/models.py`                     |
| **Классы**      | Имена, родители, мета-опции               | `class Post(models.Model)`                |
| **Поля**        | Типы, параметры, связи                    | `author = FK(User, related_name='posts')` |
| **Методы**      | Сигнатуры, что возвращают                 | `get_absolute_url()` → reverse            |
| **Views**       | Тип (CBV/FBV), queryset, логика           | `PostListView` → `Post.objects.all()`     |
| **URL**         | Паттерны, имена, view-классы              | `/blog/post/<slug>/` → `PostDetailView`   |
| **Импорты**     | Откуда что импортируется                  | Cross-app imports, dead deps              |
| **Настройки**   | Значения ключевых параметров              | `DEBUG = True`                            |
| **Проблемы**    | N+1, hardcoded secrets, отсутствие тестов | Фактическое обнаружение                   |
