Orchestrator (agent/orchestrator.md) будет:
1. Получать план напрямую от Planner (через аргументы, не файл)
2. Передавать весь output backend frontend "как есть" (без парсинга)
3. При ошибках frontend: повторить запрос к backend + лог в reports/log_status/
4. Сохранять статус в reports/orchestrator_status.md
5. Инструменты: write, read, task (как договорились)
6. Расположение: agent/orchestrator.md

Алгоритм работы Orchestrator:
1. Получить plan от Planner (в аргументах)
2. Для каждой задачи:
   a. Вызвать @backend-hybrid → получить output
   b. Проверить наличие "КОНТЕКСТ ДЛЯ ФРОНТЕНДА" в output
   c. Вызвать @Django-HTMX-Frontend-Architect с output backend
   d. Если frontend ошибка → повторить с backend (max 3 раза)
   e. Логировать результат в reports/log_status/
   f. Обновить orchestrator_status.md
3. Отчет о завершении
