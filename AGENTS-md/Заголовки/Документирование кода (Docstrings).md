1. **Фиксация формата Docstrings (Раздел 10):** Если не указать конкретный стиль (Google, Sphinx или NumPy), агент будет в одном файле использовать один стиль, в другом — другой. **Совет:** для Python лучше всего выбирать стиль **Google**, он читается легче всего и отлично парсится IDE.
## Документирование кода (Docstrings)

- **Обязательное правило:** Пиши Python docstrings **строго на русском языке** для *каждого* класса, метода и функции (включая приватные, если их логика не очевидна из названия).
- **Формат:** Используй стиль **[Google / Sphinx / NumPy — *оставьте один, например Google*]**.
- **Содержание:**
  - Кратко опиши назначение.
  - Укажи параметры (`Args`), возвращаемое значение (`Returns`) и возможные исключения (`Raises`).
  - *Запрет:* Не пиши бессмысленные docstrings вроде "Возвращает результат функции". Пиши смысловое описание бизнес-логики.
