## 4. Рабочий процесс Агента (Workflow)
При получении задачи выполняй следующие шаги:
1. **Анализ:** Изучи существующий код и связанные файлы. Не пиши код, пока не поймешь контекст.
2. **Планирование:** Кратко опиши план действий (в виде списка).
3. **Реализация:** Пиши код небольшими, логическими блоками.
4. **Проверка:** После написания кода *обязательно* запусти тесты и линтеры через CLI, чтобы убедиться, что ничего не сломано.
5. **Рефлексия:** Если тесты упали, проанализируй ошибку, исправь её и запусти тесты снова. Не сдавайся после первой неудачи.

## 6. Ограничения и "НИКОГДА не делай" (Табу)
- **НИКОГДА** не изменяй файлы конфигурации окружения (`.env`, `docker-compose.yml`) без явного запроса.
- **НИКОГДА** не удаляй существующие рабочие тесты.
- **НИКОГДА** не используй устаревшие методы или библиотеки (всегда проверяй актуальную документацию).
- **НИКОГДА** не оставляй `TODO` или `FIXME` без создания соответствующей задачи (или не создавай их вовсе, если не попросил пользователь).
- **НИКОГДА** не пиши "заглушки" (mock-данные или пустые функции) вместо реальной логики, если не указано иное.
- **НИКОГДА** не предполагай имена файлов или структуру — всегда читай директорию (`ls` / `find`) перед редактированием.

## 7. Git и Коммиты
- Используй формат **Conventional Commits** (например: `feat: add user auth`, `fix: resolve db connection leak`).
- Коммиты должны быть атомарными (один коммит = одна логическая change).
- Пиши понятные сообщения коммитов на [английском / русском] языке.
- Не коммить сгенерированные файлы, `node_modules`, `.venv`, `__pycache__`.

## 8. Обработка ошибок и Edge-cases
- Всегда предусматривай обработку ошибок (try/catch, Result monad, etc.).
- Логируй критические ошибки, но не логируй чувствительные данные (токены, пароли).
- Если задача неоднозначна, **ЗАДАЙ УТОЧНЯЮЩИЙ ВОПРОС** пользователю, прежде чем писать код.
